## Exact source and field contracts

Extend existing `CBPartnerFlow` and `CBPartnerNetwork` Kermit events, not a new logger facade. Never use a global singleton or guess debug eligibility. Operational T1 summaries remain per Doc23.

**API request:** Show complete method; code-owned static bootstrap route may appear as literal after field-level privacy review, but a backend-provided endpoint must be transformed using an explicitly reviewed safe route-template allowlist; redact unknown/path parameters/query, do not emit untrusted URL string. Headers shown **only if actually applied**, from final request boundary, with name allowlist and redacted runtime metadata/Authorization values; never fabricate headers. Body: show `absent/present`, safe key/type structure when available; no raw arbitrary body. Response: show actual HTTP status and **source-derived structurally faithful redacted representation**, never full raw body, OTP, tokens, phone, device ID, arbitrary free text or error message in terminal. Label clearly `SANITIZED RESPONSE`, not `RAW SERVER JSON`.

**Method execution events:** `event=trace.step` with `owner` and `method` selected strictly from compile-time known literals per instrumented entry/exit; stage `enter|exit|failed|cancelled`, existing correlation and optional `outcome`; no runtime reflected stack dumps or arbitrary class/method strings. Prefer meaningful boundaries over each trivial helper. Distinguish transport, repository, mapper and Store from UI/render milestones. Events must be emitted at real call points and preserve cancellation.

**SDUI screen:** emit validated screen ID and template ID only if strict safe-ID grammar (otherwise `[redacted]`), registered template/component/section/group/element/content type tokens, hierarchy including header/body/footer and direct children, leading/trailing accessories, property-name/type/presence whitelists, sanitized binding reference kinds and action event/type plus safe navigation mode/endpoint template. Do not include values from input bindings, full backend-driven text, validation messages, URLs, action payload data or arbitrary response text. If mapped response is not a screen, output real destination/payload shape and do not synthesize one. Enforce bounded output (candidate max 100 nodes and 16KiB; exact budget confirmed by tests). A screen response must not be conflated with a successfully rendered screen.

**Interaction:** instrument actual element/content callback origin; attach safe element ID, rendered action trigger and type only where supported by real callback. `DynamicStore` and `DynamicActionExecutor` already log real action and handler; reuse, don't duplicate or synthesize class chain. Correlate to HTTP and navigation. Need to enumerate actual click, long click, text links, input/change, and content callbacks, then instrument only supported origins. Do not log user-entered values.

**Navigation/splash:** splash Composable visibility/commit landmark, bootstrap store call, repository and mapper handoff, dynamic navigation entry screen identity, actual renderer registration and Compose SideEffect. Existing navigation and MVI/UDF behavior unchanged. No UI inspector.
